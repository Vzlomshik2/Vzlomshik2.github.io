# NTS ENGINE PASSPORT v2

Версия учитывает выбранные требования:
- роли кабинета: `mechanic`, `quality`, `admin`;
- фотографии в паспорте;
- выгрузка PDF;
- публичный паспорт с полным набором технических полей, историей и публичными фотографиями.

## Важно: это исходный проект, не опубликованный сайт
Архив содержит готовую основу интерфейса и SQL-схему. Общая база, вход сотрудников и публичный поиск заработают после подключения вашего проекта Supabase и публикации файлов на хостинге. Из чата невозможно подключить неизвестный аккаунт Supabase или опубликовать сайт от вашего имени без доступа.

## 1. Создать базу
1. Откройте https://supabase.com и создайте проект.
2. В проекте откройте SQL Editor.
3. Скопируйте весь файл `supabase/schema.sql` и нажмите Run.
4. В Settings → API скопируйте Project URL и anon/public key.
5. Вставьте их в `config.js`.
   Не используйте `service_role` key в браузере ни при каких обстоятельствах.

## 2. Создать сотрудников
1. В Supabase откройте Authentication → Users.
2. Создайте аккаунты сотрудников вручную. Публичную регистрацию не включайте.
3. Скопируйте UUID каждого пользователя.
4. Первому аккаунту назначьте admin через SQL Editor:
   `insert into public.staff_roles(user_id,role,display_name) values ('UUID','admin','NTS Admin');`
5. Администратор сможет назначать роли остальным через вкладку «Сотрудники».

## 3. Опубликовать сайт
Загрузите все файлы проекта (с сохранением структуры папок) на статический хостинг, например Netlify или Cloudflare Pages. Для первой публикации проще использовать Netlify Drop с компьютера. С Android удобнее сначала загрузить архив в облако/на компьютер или воспользоваться веб-интерфейсом GitHub.

## Роли
- `mechanic`: создаёт паспорта, добавляет историю и фотографии; не утверждает статусы VERIFIED/REBUILT.
- `quality`: проверяет данные и может менять статус; отвечает за корректность отметки контроля качества.
- `admin`: полный доступ, включая назначение ролей и удаление записей.

## Что открыто публично (выбрано вами: FULL)
Публичный поиск выдаёт все технические поля паспорта, статус, номер заказа, описание, историю работ и фотографии с `is_public=true`.
Система намеренно не публикует email сотрудников, ID пользователей и внутренние служебные данные. Не заносите ФИО, телефон, адрес, VIN, документы владельца и внутренние заметки в публичные поля.

## PDF
PDF формируется в браузере по открытому паспорту. В текущей версии в PDF попадают основные поля и история; фотографии пока открываются в цифровом паспорте, но не встраиваются в PDF.

## Перед реальной эксплуатацией — обязательные доработки
Это MVP v2, перед запуском с клиентскими данными требуется техническая проверка SQL/RLS и тестирование. В частности:
- включить строгий аудит изменений и запретить механику самостоятельно менять технические поля после утверждения;
- разделить публичные и внутренние фотографии/заметки;
- сделать серверную генерацию PDF с контрольным номером и неизменяемой версией документа;
- подписывать статусы VERIFIED/REBUILT отдельным QC-событием, а не только изменением поля;
- добавить резервное копирование, лимиты запросов и CAPTCHA/защиту от перебора номеров;
- протестировать права доступа под каждой ролью и анонимным посетителем.

Статус NTS ENGINE VERIFIED / REBUILT — внутреннее подтверждение процесса NTS, а не государственная сертификация и не обещание отсутствия будущих неисправностей.
